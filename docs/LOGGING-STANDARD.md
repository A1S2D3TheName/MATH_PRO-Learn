# Стандарт журнала практики

Что, куда и в каком виде записывается. Нарушение формата — повод провалить `tools/journal.py check`.

## 1. Структура сессии

```
journal/
  INDEX.md                              одна строка на сессию
  2026/
    2026-12-12_1100/                    <дата>_<ЧЧММ начала>
      meta.json                         машинная сводка (поля — §2)
      session.md                        план → ход → итог (по шаблону)
      transcript.md                     чат: дословно ученик, сжато агент (§3)
      observations.md                   4 раздела (§4)
      proposals.md                      предложения/дефекты банка и стандарта (может быть пустым с пометкой)
      work/                             файлы ученика: решения, код, фото-описания
      addendum-YYYY-MM-DD.md            поправки после закрытия (необязателен)
```

Других файлов и папок в сессии не создавать. Имена файлов — латиница, кроме `work/`.

## 2. `meta.json`

```json
{
  "id": "2026-12-12_1100",
  "date": "2026-12-12",
  "start_time": "11:00",
  "end_time": "14:00",
  "duration_min": 180,
  "mode": "challenge",
  "status": "closed",
  "closed_late": false,
  "phase_at_start": "learning",
  "completeness": "verbatim",
  "items": [
    {
      "item_id": "math-prm800k:...",
      "origin": "bank",
      "section": "nt",
      "stage": 5,
      "outcome": "solved_unaided",
      "hints_max_level": 1,
      "hint_count": 2,
      "help_requests": 1,
      "self_corrections": 1,
      "confidence_before": 2,
      "answer_checked_by": "code"
    }
  ],
  "student_report_present": true,
  "files_touched": ["learner/state.yaml", "learner/competency-map.yaml"]
}
```

Допустимые значения:
* `mode`: `assessment | challenge | learn | review | free`
* `status`: `open | closed`
* `completeness`: `verbatim | reconstructed`
* `origin`: `bank | agent-generated | student`
* `outcome`: `solved_unaided | solved_hinted | partial | unsolved | revealed | abandoned`
* `answer_checked_by`: `code | by_hand | not_checked`
* `confidence_before`: 1 (не уверен) – 3 (уверен) или `null`

## 3. `transcript.md`

Заголовок: `completeness: verbatim|reconstructed`. Далее блоки по порядку, **одна реплика — один блок**:

```
[11:07] СТ: «текст ученика дословно»
[11:08] АГ·Q: вопрос агента
[11:12] АГ·hint L1: …
[11:15] СТ: …                                  ← событие: attempt
```

Метки агента: `Q` вопрос · `hint L<0-4>` подсказка · `check` проверка шага · `info` справка ·
`reveal` раскрытие · `task` выдача задачи · `meta` организационное.
События пишутся в конце блока стрелкой `← событие: <тип>`: `attempt`, `help_request`,
`self_correction`, `confidence <1-3>`, `stuck`, `aha`, `error:<тип>`.

Время — **со слов ученика** (он называет старт и конец). Метки времени в блоках — приблизительные,
расставляются, только если ученик их указывает; иначе пиши порядковый номер `[#12]`.

## 4. `observations.md`: четыре раздела

Строго эти заголовки и в этом порядке:

1. **Со слов ученика** — дословные цитаты результата и наблюдений при закрытии, плюс любые самооценки в ходе занятия, по пунктам. Ничего не добавлять и не править.
2. **Факты** — проверяемые утверждения; у каждого ссылка `(transcript #N)` или `(meta item X)`. Примеры: «Задача X решена без подсказок (#31–#44)», «Ошибка типа: деление на ноль не рассмотрено (#22)», «Прогноз сложности: 2/3, итог — потребовалась подсказка L2».
3. **Интерпретации агента** — с `confidence: low|med|high` и опорой на факты: «Склонен к ранней алгебраической записи без малых случаев (low; факты: #12, #28)». Без фактов — не писать.
4. **Гипотезы на проверку** — формулировка для следующего агента: что проверить, какой задачей. Они попадают в `learner/state.yaml: open_questions`.

Запрещено: ярлыки о личности/способностях («умный», «ленивый», «не математик»), диагнозы,
сравнения с нормой, предсказания, не опирающиеся на журнал.

## 5. `session.md`

Три раздела: **План** (режим, выбор задачи и обоснование, критерии), **Ход** (по каждой задаче:
условие или ссылка `item_id`, что делал ученик по шагам, подсказки, итог), **Итог** (outcome по каждой
задаче, время, что обновлено в `learner/`). Ссылки на `transcript #N` обязательны.

## 6. `learner/`

* `state.yaml` — единственная точка входа для следующего агента: фаза, фронтир, последняя сессия, подсказка «что предлагать дальше», открытые вопросы.
* `competency-map.yaml` — по разделам `sections` из `curriculum/tree.yaml` (и отдельно `python`): `proven_level`, `proven_with_help`, `ceiling`, `confidence`, `evidence[]` (список `{session, item_id, outcome, note}`).
* `review-queue.yaml` — элементы к повторению: `{item_id|topic, due, streak, last_session}`.
* `problems-seen.jsonl` — одна JSON-строка на задачу в сессии: `{"session","item_id","outcome","revealed","hints_max_level","date"}`. Только дозапись.

## 7. `journal/INDEX.md`

Таблица: `| сессия | режим | длительность | задач | итог (≤ 100 знаков) | ссылка |`. Дозапись одной строки при закрытии.

## 8. Принципы

1. **Источник истины — `transcript.md`.** Всё остальное выводится из него.
2. **Append-only.** Закрытую сессию не меняют; поправки — `addendum-*.md`.
3. **Каждая оценка имеет ссылку на доказательство.**
4. **Три сорта текста не смешиваются**: слова ученика, факты, интерпретации.
5. **Пустых разделов нет**: «нет данных» + причина.
6. **Объём не цель**: максимально полно ≠ максимально длинно. Нет воды, нет пересказа учебников.
