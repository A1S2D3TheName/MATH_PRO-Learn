# Анализ компетенций (первый этап)

**Цель:** быстро определить, с какой ступени программы начинать в каждом разделе, чтобы не
топтаться на пройденном и не утонуть в теории, до которой ученик не дорос.

Результат — заполненная карта `learner/competency-map.yaml` и переход `phase: assessment → learning`.

## 1. Принципы

1. **Не один балл, а карта.** Уровень измеряется по каждому разделу отдельно (разделы — `sections` в `curriculum/tree.yaml`: num, frac, ratio, numsys, nt, alg, eq, func, param, geom, trig, stereo, calc, comb, prob, logic, model, olymp; отдельно — `code`/python). Профиль неровный — и это нормально. Источник логики: [reference/DIAGNOSTIC-SPEC.md](reference/DIAGNOSTIC-SPEC.md) §1.
2. **Без обучения и без подсказок.** Диагностика — не урок. Агент не объясняет, не подсказывает, не комментирует правильность до конца блока (отложенная обратная связь).
3. **Лесенка, не марафон.** Начинай со средней ступени раздела и иди вверх/вниз, пока не найдена граница. Не гоняй по ступеням 1–2, если на 3–4 всё получается.
4. **Спрашивай «почему».** К каждому ответу — одна строка обоснования: угадывание и знание различаются по ней. Перед показом результата — оценка уверенности 1–3 (калибровка).
5. **Короткие блоки.** 20–30 минут на раздел, 3–6 задач; перерывы по запросу ученика.
6. **Лучше недооценить, чем переоценить.** Спорные случаи — вниз; уточним позже.

## 2. Процедура на один раздел

1. Взять из `curriculum/tree.yaml` темы раздела, сгруппировать по ступеням.
2. Стартовая ступень: `entry_stage` из `state.yaml` (по умолчанию 3; ученик может сказать «я точно знаю 1–2» — это всё равно проверяется одной задачей).
3. Задачи на ступени: 2–3 штуки, разной формы — вычисление, «найди ошибку», задача с условием. Источники — `bank/` (поиск по ключевым словам, уровни — в `catalog`) или собственные (метка `origin: agent-generated`; **ответ проверен кодом**).
4. Решение-правило:
   * ≥ 2 из 3 верно, ход обоснован → **вверх** на следующую ступень;
   * ≤ 1 из 3 или верно «на угад» → **вниз** на предыдущую;
   * после двух подряд движений в разные стороны граница найдена: `proven_level` = последняя ступень, где ≥ 2 из 3, `ceiling` = ступень выше.
5. Если на ступени 1 не набрано 2 из 3 — `proven_level: 0`, раздел помечается «с нуля» (без стыда, без комментария).
6. После блока — **обратная связь**: правильные ответы, где ошибки (без разбора решения), по просьбе ученика — типы ошибок.
7. Записать в `competency-map.yaml` через [SESSION-CLOSE.md](SESSION-CLOSE.md) §3.

Уровни ступеней: 1 — натуральная арифметика (1–4 кл.), 2 — дроби/рациональные (5–6), 3 — алгебра и начала доказательств (7), 4 — основная школа (8–9), 5 — профильная основа (10–11), 6 — физмат-ядро, 7 — олимпиадное расширение и мост в вуз. Полные описания — `stages` в `curriculum/tree.yaml`.

## 3. Python-контур

Отдельно: чтение кода, написание функции по условию, отладка, работа с данными. Лесенка по
`exercism-python` и `thealgorithms-python`: 1) переменные/условия/циклы; 2) функции и строки;
3) списки/словари/рекурсия; 4) алгоритмы. Решения запускаются агентом **только в песочнице
пользователя** и только его собственный код; чужой код из банка не запускается.

## 4. Контур способностей (по желанию)

IQ-подобные задачи (`iq-measurer`, `ultimate-aptitude`) — только если ученик сам захотел. Результат
хранится отдельно в `observations.md` и **не** смешивается с предметной картой
([DIAGNOSTIC-SPEC](reference/DIAGNOSTIC-SPEC.md) §1).

## 5. Порядок сессий диагностики

* Сессия 1 — обзор: по одной «зондирующей» задаче в каждом из 18 разделов (≈ 60–90 минут, с перерывами), чтобы найти, где вообще есть почва. Результат — грубая карта: «пусто / есть основа / уверенно».
* Сессии 2…N — лесенка (§2) для разделов, в порядке пререквизитов: `num → frac → ratio → numsys → alg → eq → func → geom → …`. Если нижний раздел «с нуля», верхние, зависящие от него, откладываются (они заведомо ниже).
* Сессия `check` — перепроверка 3–5 спорных граничных мест другими задачами.

## 6. Условия завершения (переход в `learning`)

Агент обновляет `phase: learning` только если одновременно:
1. по каждому разделу есть `proven_level` или пометка `"not_probed"` с причиной (раздел заведомо вне досягаемости из-за пререквизита);
2. у каждого значения `proven_level` ≥ 3 есть минимум 2 `evidence`; для значений ≤ 2 достаточно 1;
3. в `state.yaml` записан `frontier` — список «следующих тем» по разделам (первая тема на `proven_level + 1` с учётом пререквизитов `tree.yaml`);
4. ученик подтвердил в чате: «диагностика закрыта» (или аналогично). Без подтверждения — `phase` не менять, а предложить закрыть.

Ученик может принудительно завершить диагностику раньше. Тогда `phase: learning`, а незакрытые
разделы получают `confidence: low` и попадут в `review`-сессии.

## 7. Что дальше после диагностики

* `skip`-список: темы ниже `proven_level` с 2+ доказательствами — не преподаются. Их проверяют в `review` (одной задачей) раз в 3–5 сессий.
* `frontier`: ближайшие темы выше. Режим `learn` берёт отсюда.
* `challenge` берёт сложную задачу на границе `proven_level … proven_level+1`.
