# Протокол закрытия сессии

Срабатывает на фразу вида: *«время 14 00, закрывай сессию, я всё. Вот такой результат пока что получился и такие вот наблюдения: …»*.

Цель — зафиксировать занятие **максимально полно и без домыслов**, чтобы любой другой агент
через полгода понял, что происходило и на чём основаны оценки.

## 1. Что ты получаешь от ученика

* `end_time` — время закрытия («14 00»).
* **Результат** (со слов ученика): что получилось/не получилось.
* **Наблюдения** (со слов ученика): что он заметил про себя, что было трудно/легко.

Это **слова ученика** — записываются в `observations.md` дословно, в разделе «Со слов ученика».
Ничего из них не исправляй и не «причёсывай». Если ученик ничего не добавил — запиши «не добавил»,
но не придумывай.

## 2. Шаги (строго по порядку)

1. **Остановить занятие.** Не начинай новых вопросов. Допустимо одно уточнение к словам ученика, если оно нужно для записи (например, «какую задачу ты называешь "второй"?»).
2. **Дописать `transcript.md`** до конца. Если часть реплик утрачена или не могла быть записана — не восстанавливай по памяти: поставь в начале файла `completeness: reconstructed` и перечисли, что утрачено. Иначе `completeness: verbatim`.
3. **Собрать `work/`**: все решения, наброски, код ученика, которые были в чате.
4. **Заполнить `meta.json`** (машинная сводка): через `python tools/journal.py close <папка> --time HH:MM`, затем впиши вручную поля: `items`, `hints`, `outcome` по каждой задаче, `help_requests`, `self_corrections`. Длительность считается из `start_time` и `end_time`.
5. **Написать `session.md`** по шаблону: План → Ход (по задачам: условие, что делал ученик, подсказки, итог) → Итог. Только факты, со ссылками на строки `transcript.md`.
6. **Написать `observations.md`**:
   * «Со слов ученика» — дословно;
   * «Факты» — измеримое (решено/нет, число подсказок, время, ошибки типа…), каждое с ссылкой на transcript;
   * «Интерпретации» — с пометкой уверенности (`low`/`med`/`high`) и **опорой на факты**; допустимы только если есть ≥ 1 факт;
   * «Гипотезы на проверку» — что проверить в следующей сессии (становятся заданиями следующему агенту).
7. **Обновить `learner/`** (только по правилам §3):
   * `problems-seen.jsonl` — по одной строке на задачу;
   * `competency-map.yaml` — по каждому доказательству;
   * `review-queue.yaml` — новые элементы по интервалам;
   * `state.yaml` — `last_session`, `last_session_date`, `sessions_total`, `frontier`, `next_suggested`, `open_questions`; фаза — только если выполнены условия ASSESSMENT.
8. **Дописать строку в `journal/INDEX.md`** (формат — внутри файла).
9. **Проверить**: `python tools/journal.py check <папка>` → должно быть `OK`. Исправить, если нет.
10. **Ответить ученику** кратко (≤ 12 строк): что зафиксировано (список файлов), 2–3 главных факта сессии, что рекомендовано на следующий раз (из гипотез), что не удалось зафиксировать и почему. Никаких оценок «ты молодец / плохо».

## 3. Правила обновления `learner/`

**`competency-map.yaml`** — запись `evidence` добавляется всегда; поле `level` меняется по правилам:

| Событие | Что допустимо |
|---|---|
| Решил задачу раздела на ступени N **без подсказок** и объяснил ход | `proven_level` может стать N, если уже есть ≥ 2 независимых успеха на ступени N−1 или ниже в этом разделе, либо N ≤ 2 |
| Решил с подсказкой L1–L2 | `proven_with_help` = N; `proven_level` не меняется |
| Решил с подсказкой L3+ или после `revealed` | только `seen`, плюс постановка в очередь повторения |
| Не решил, попытки были | `attempted` + тип ошибки; уровень не снижается по одной неудаче |
| Две независимые неудачи на ступени N подряд | можно записать `ceiling: N` (потолок), с `confidence: med` |

Правило осторожности: **одна задача уровень не меняет**. Любая запись `level` требует ссылки
`session` + `item_id`. Агент не повышает и не понижает уровень «по ощущению».

**`review-queue.yaml`** — после успешного решения: следующая проверка через `1 → 3 → 7 → 16 → 35 → 75` дней
(индекс по числу последовательных успехов); после неудачи или `revealed` — через 1 день, счётчик в 0.
Источник схемы — [reference/DIAGNOSTIC-SPEC.md](reference/DIAGNOSTIC-SPEC.md) (этап `delayed`).

**`state.yaml`** — меняй только перечисленные поля; `phase`, `stage_current` — только по условиям
из [ASSESSMENT.md](ASSESSMENT.md) §6.

## 4. Если что-то пошло не так

* Ученик пишет «закрывай» без времени — спроси одним вопросом время; если ответа нет, закрой со `end_time: null` и пометкой `time_unknown`.
* Не хватает данных для обязательного раздела — запиши «нет данных» и **причину**. Пустой раздел недопустим.
* Сессия прервана (ученик пропал) — при следующем открытии закрой её задним числом (`closed_late`), содержимое — только то, что есть в `transcript.md`.
* Ученик хочет что-то поправить после закрытия — не правь файлы: создай `addendum-<дата>.md` в той же папке.

## 5. Чего не делать при закрытии

* Не пересказывать занятие «своими словами» вместо фиксации. Источник — `transcript.md`.
* Не добавлять в `observations.md` оценки личности, мотивации, «потенциала».
* Не менять `docs/`, `bank/`, `curriculum/`. Предложения — в `proposals.md`.
* Не пропускать шаг 9.
