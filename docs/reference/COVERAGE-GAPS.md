# Пробелы покрытия и что с ними делать

Документ отвечает на вопрос «что не закрыто». Каждый пункт — с указанием,
чем он закрыт частично, чего не хватает и что можно сделать руками.

## 1. Русскоязычный материал — главный пробел

**Что есть.** `math-500-ru` даёт **индекс из 500 задач** олимпиадного уровня
на русском (10 позиций — preview-метаданные, тексты не копируются: права на
машинный перевод не подтверждены), `problems-ru` (в основном репозитории) —
оглавление задач на русском. Оба — index-only, и оба ограничены верхним
уровнем.

**Чего не хватает.** Русскоязычных задач **начального уровня**: арифметика,
дроби, проценты, отношения, задачи в тексте. Новые источники этого не
закрывают: `math-prm800k` начинается с «Prealgebra» на английском и
покрывает уровни 1–5 *сложности*, а не ступени 1–2 *программы*.

**Что искать.** Открытые русские банки: сайты школ и вузов с явной лицензией,
«Математические олимпиады» МЦНМО с условиями использования, сборники ФИПИ
(права требуют проверки — `sources/fipi-bank` в основном репозитории уже
разобран как `index-only`).

**Что можно сделать руками.** Взять 20–30 тем ступени 1–2 из `tree.yaml` и
написать по 3 задачи на тему с ответами и разборами. Это работа на 2–3
задачи в час, но она даёт то, чего нет ни в одном найденном банке: русский
язык, ступени 1–2, единый формат.

## 2. Пары для измерения переноса

**Что есть.** Задачи есть (`trecut-math` — 4 000, из них 2 000 пар
«решаемая/нерешаемая»; `math-prm800k` — 12 500 по предметам и уровням;
`exercism-python` — 163).

**Чего не хватает.** Явных пар «исходная задача → задача на тот же принцип
в другом контексте». Источники дают материал, но не структуру переноса.

**Что можно сделать руками.** Правило: для каждой задачи с уровнем 3–5 в
`math-prm800k` подобрать одну задачу того же предмета и уровня, но с другой
формулировкой; такие пары полностью машинно-извлекаемы по тегам
`subject` + `level` + `path` — **но отбирать их должен человек**, потому что
«тот же принцип» формально не задаётся.

`trecut-math` — единственный источник, где пары уже есть, и они парные по
принципу, а не по совпадению темы.

## 3. Каталог ошибок в едином формате

**Что есть.** `ai-tutor-socratic` — 33 заблуждения с идентификаторами
`M_<CONCEPT>_<NN>`; `math-prm800k` — 3 817 записей с пошаговыми метками
верности (включая ошибочные шаги); `errors/catalog.yaml` в основном
репозитории — свой формат.

**Чего не хватает.** Сопоставления двух каталогов: идентификаторы из
`ai-tutor-socratic` не связаны с ID из `errors/catalog.yaml`, а метки шагов
PRM800K не привязаны к типам ошибок MATH_PRO.

**Что можно сделать руками.** Сопоставление ~33 заблуждений с каталогом
ошибок — это час работы. Шаги PRM800K сопоставляются с каталогом
автоматически по совпадению формулировок, но результат требует вычитки.

## 4. Нормы времени решения

**Что есть.** Ничего.

**Чего не хватает.** Проверенных нормативов «сколько секунд на задачу
уровня N в домене D». `ultimate-aptitude` содержит таймеры, но это
экзаменационные тайминги GMAT, а не учебные нормативы. `iq-measurer`
содержит лимиты времени по доменам способностей — но это другой контур.

**Почему это важно.** Время в измерениях стоит как «флаг», а не как балл
(`specs/DIAGNOSTIC-SPEC.md`, §4). Чтобы превратить его в балл, нужны
нормативы. Собрать их можно: прогнать банк на группе известного уровня и
посчитать распределение — но это отдельная исследовательская работа (психометрическая
калибровка), а не сбор данных.

## 5. Психометрическая валидность банков способностей

**Что есть.** `iq-measurer` (200 вопросов, 4 домена), `aptitude-test-platform`
(600 вопросов, 2 раздела), `ultimate-aptitude` (1 098 вопросов).

**Чего не хватает.** Ни у одного нет опубликованной психометрической
проверки. `iq-measurer` прямо признаёт, что его формула
«IRT-вдохновлённая» и не является IRT; `aptitude-test-platform` использует
машинно сгенерированные отвлекающие варианты без проверки качества.

**Вывод.** Эти банки нельзя использовать для **измерения** способностей.
Их можно использовать как **материал** для тренировки (то есть как набор
задач), но не как инструмент оценки. В `specs/DIAGNOSTIC-SPEC.md` §1 это
зафиксировано: контур способностей отделён от предметного.

## 6. Промежуточный уровень по сложности в `ultimate-aptitude`

**Что есть.** 1 098 вопросов, но распределение сложности смещённое:
572 «hard», 522 «very-hard», 4 «medium».

**Почему это важно.** Банк не годится для входной диагностики: новичку
достанется «very-hard». Использовать его стоит на среднем и верхнем уровне
(ступени 4–6), а для ступеней 1–2 — другие источники.

**Что можно сделать руками.** В upstream есть процедурные генераторы
(`js/generators.js`), которые строят вопросы из шаблонов и строят ответ
по построению. Генераторы — код (MIT), их можно было бы перенести и
подключить к `mathpro` для бесконечной практики; это отдельная задача и
отдельное решение по лицензии (MIT на код, CC BY на вопросы).

## 7. Проверка ответов для нестандартных форм

**Что есть.** `mathpro/grading/` (свой код), `prm800k/grading/math_normalize.py`
(MIT), `exercism-python` (машинные тесты для кода).

**Чего не хватает.** Единой политики для: ответа «да/нет», множественного
выбора, числового ответа с единицами измерения, геометрических объектов,
задач «введите выражение». В `ultimate-aptitude` 1 098 вопросов — из них
часть с вариантами, часть с числовым ответом, часть с текстовым. Каждая
форма требует своего правила приведения.

**Что можно сделать руками.** Сопоставить `mathpro/grading/answers.py` с
`math_normalize.py` из PRM800K — это час работы и даёт проверенный набор
случаев, а не самодельные regex.

## 8. Упражнения по Python с математическим содержанием

**Что есть.** `exercism-python` (163 упражнения, общие задачи программирования),
`thealgorithms-python` (1 287 реализаций), `sympy-books` (8 разделов).

**Чего не хватает.** Упражнений, где **содержательная часть — математика**,
а Python — инструмент: численные методы, статистика, моделирование,
символьные вычисления. `sympy-books`closest всего, но там 8 разделов.

**Что можно сделать руками.** Взять 2–3 темы из `mapping/code.yaml` и
собрать по 3–5 задач вида «реализуй метод и проверь на трёх примерах» с
численными эталонами.

## 9. Доказательства средней сложности

**Что есть.** `forallx` — теория (логика высказываний и предикатов, 93
раздела), `minif2f` и `imosllean4` — верхний край (олимпиадный уровень).

**Чего не хватает.** Простых и средних задач «докажите, что…»: например,
доказательство свойства дроби или что последовательность возрастает.
`forallx` содержит упражнения, но они не выделены в каталоге
(см. `sources/forallx/REPORT.md`: разбор LaTeX грубый, упражнения ищутся по
ключу `exercise`).

**Что можно сделать руками.** Выделить упражнения из `forallx` вручную и
оформить как каталог — это несколько часов работы с регулярным выражением
по исходному `.tex`.

## 10. Сводка приоритетов

| приоритет | пункт | почему |
|---|---|---|
| 1 | русский материал ступеней 1–2 | без него программа не начинается с нуля на родном языке |
| 2 | сопоставление каталогов ошибок | без него блок error diagnosis не работает |
| 3 | пары для переноса | без них измерение transfer нечем измерять |
| 4 | политика приведения ответов | без неё часть задач невозможно проверить автоматически |
| 5 | упражнения «математика на Python» | закрывает половину блока Python |
| 6 | нормативы времени | улучшает измерение, но не блокирует его |
| 7 | выделение упражнений `forallx` | закрывает пробел в логике |

Пункты 1–5 — ручная работа, которую нельзя делегировать коду: они требуют
предметного суждения. Это честный вывод: найти готовые данные можно было,
а вот довести их до измеримого вида — нет.
